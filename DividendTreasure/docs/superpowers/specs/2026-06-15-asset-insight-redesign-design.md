# 资产透视重做设计

## 背景

当前项目中已经存在 [AssetInsightView](../../../../DividendTreasure/Views/AssetInsight/AssetInsightView.swift) 和 [AssetInsightService](../../../../DividendTreasure/Services/AssetInsightService.swift)，但功能只完成了一半：

- 统计页已经有「资产类型 / 行业 / 市场」三个维度的分布计算和图表容器。
- 首页 `AssetOverviewCard` 只展示总市值、年度股息、组合股息率和股息率 `Top 3`，没有承接资产透视入口价值。
- 持仓的 `industry`、`assetType` 等字段没有在主要导入链路中自动补齐，导致行业分布在真实数据里长期退化为「其他」。
- 统计服务的 `getOverview()` 已定义 `topAssetType`、`topIndustry`、`topMarket`，但目前没有任何页面消费。

结果是：代码里看起来「资产透视已实现」，用户体验上却像「行业占比没有真正做完」。

## 用户已确认的设计决策

本次重做已通过对话和原型确认以下方向：

- 总体方案采用「双层联动」。
- 首页提供精简但高价值的资产透视概览。
- 详情页提供完整分析工作台。
- 首页第二层信息采用「行业优先更大，同时并列展示集中度」。
- 详情页支持点击资产类型 / 行业 / 市场分类后下钻到该分类下的持仓列表。

## 目标

1. 让首页在不拥挤的前提下，显著提升资产透视的存在感。
2. 让详情页从「静态图表页」升级为「可切换、可下钻的分析工作台」。
3. 打通上游数据归类，保证行业占比、市场分布、资产类型分布在真实数据下可用。
4. 保持当前项目的 SwiftUI + SwiftData 架构，不引入新的复杂基础设施。

## 非目标

- 本次不做跨时间维度的历史资产变化趋势。
- 本次不做自定义维度管理。
- 本次不做多币种换算。
- 本次不接入新的第三方图表库。

## 信息架构

### 首页：资产透视概览卡

首页仍保留一张「资产透视」卡片，但内容升级为两层结构：

#### 第一层：组合总览

- 总市值
- 年度股息
- 组合股息率

这一层沿用现有卡片的核心价值，不改变用户已熟悉的阅读路径。

#### 第二层：分布洞察

- 主视觉：行业占比
- 并列补充：前几大持仓集中度
- 轻量摘要：市场分布、资产类型分布

建议展示形式：

- 行业占比：横向占比条或小型环形图 + `Top 3` 标签
- 集中度：`Top 1` / `Top 3` / `Top 5` 持仓占比中的一个主指标
- 市场分布与资产类型分布：用简短标签摘要，不抢主视觉

#### 首页交互

- 整张卡片可点击进入资产透视详情页。
- 行业占比区域和集中度区域可选做局部点击跳转；若实现成本偏高，首版可统一进入详情页后定位默认维度。

### 详情页：资产透视工作台

详情页从单一统计页升级为工作台结构，包含以下模块：

#### 顶部控制区

- 维度切换：资产类型 / 行业 / 市场
- 数值切换：金额 / 占比
- 排序方式：按市值排序（首版），后续可扩展按股息、按数量

#### 图表区

- 环形图：用于看整体结构
- 条形图：用于看分类对比

两个图表消费同一份当前维度数据，避免数据解释不一致。

#### 分类列表区

展示当前维度下的所有分类，列表项包含：

- 分类名称
- 市值
- 占比
- 该分类包含的持仓数量

点击列表项后，进入下钻状态。

#### 下钻区

进入某个分类后，显示该分类下持仓列表，列表项至少包含：

- 代码
- 名称
- 市值
- 当前股息率
- 持仓数量

同时提供「返回分类总览」操作。

## 数据与服务设计

### 1. 资产透视统计服务重构

保留 `AssetInsightService` 作为统计主入口，但从「几个独立函数」升级为「概览 + 维度分析 + 下钻」三个层次：

- `overview(for holdings:)`
  - 首页概览数据
  - 包含总市值、总股息、组合股息率、行业 `Top N`、市场分布摘要、资产类型分布摘要、集中度指标
- `breakdown(for dimension:, holdings:, mode:)`
  - 详情页当前维度统计
- `drilldown(for dimension:, category:, holdings:)`
  - 返回某个分类下的持仓列表

### 2. 数据清洗与归类

行业占比失效的根因不是图表，而是上游字段为空或长期为「其他」。本次需要补齐以下链路：

- 手动新增持仓：搜索选股后尽可能自动填充 `industry` 和 `assetType`
- OCR 导入：导入确认后，异步补充行业 / 资产类型 / 市场信息
- 已有持仓：统计时对空值和无效值做兜底归并，统一归类到「其他」

### 3. 资产类型归并规则

首页概览和详情页都需要统一资产类型口径，避免首页看的是粗分类、详情页看的是细分类但没有说明。

建议保留两层：

- 概览层：股票 / 基金 / 债券 / 现金 / 其他
- 明细层：股票 / ETF / REITs / 指数基金 / 债券 / 货币基金 / 现金 / 其他

详情页在「资产类型」维度下支持基础 / 细分切换。

### 4. 集中度定义

首页集中度采用以下规则：

- 主指标：前 3 大持仓市值占总市值比例
- 补充指标：最大单一持仓占比

原因：

- 用户最关心的是组合是否过度集中。
- `Top 3` 比 `Top 5` 更简洁，适合首页。
- 最大单一持仓可作为风险提醒，但不独占主视觉。

## UI 结构设计

### 首页卡片建议结构

1. 标题区：资产透视 + 查看详情
2. 总览指标区：总市值、年度股息、组合股息率
3. 洞察区：
   - 大卡：行业占比
   - 小卡：前 3 大持仓集中度
4. 摘要区：
   - 市场分布
   - 资产类型分布

### 详情页建议结构

1. 顶部维度切换
2. 金额 / 占比切换
3. 当前维度图表区
4. 当前维度分类列表
5. 下钻持仓列表（仅在用户点击分类后出现）

## 空状态与异常状态

### 空持仓

- 首页：资产透视卡仍保留，但显示「暂无持仓数据」
- 详情页：显示空状态页，引导先添加持仓

### 归类缺失

- 若某只持仓缺少行业或资产类型，统计时并入「其他」
- 若某个维度下只有「其他」，页面仍正常展示，不隐藏模块

### 图表数据过少

- 只有 1 个分类时，图表仍展示，列表同步展示
- 分类过多时，首页仅展示 `Top N`，详情页展示完整列表

## 测试与验证要求

### 单元测试

至少覆盖以下场景：

1. 行业分布能正确汇总市值和占比
2. 集中度计算正确
3. 空行业 / 空资产类型会被归并为「其他」
4. 下钻结果仅返回当前分类持仓
5. 首页概览统计与详情页同口径

### UI 验证

至少验证以下场景：

1. 首页资产透视卡在有持仓时展示完整两层结构
2. 首页在无持仓时展示空状态
3. 详情页维度切换、金额 / 占比切换生效
4. 点击行业 / 市场 / 资产类型后可以下钻
5. 下钻后可以返回总览

## 实施拆分建议

后续实现计划建议拆成 4 个阶段：

1. 数据与统计层
   - 重构 `AssetInsightService`
   - 加入概览、集中度、下钻支持
2. 上游归类补全
   - 打通搜索、OCR、手动新增链路的行业 / 资产类型自动补全
3. 首页卡片改造
   - 重做 `AssetOverviewCard`
4. 详情页工作台改造
   - 重做 `AssetInsightView`
   - 增加下钻交互

## 风险与权衡

- 最大风险不在 UI，而在真实持仓数据的行业字段质量。
- 如果上游归类补全不做，图表即便渲染正确，用户仍会看到大量「其他」。
- 首页承载的信息比现在更多，必须控制视觉层级，避免 Dashboard 过重。
- 详情页加入下钻后，状态管理复杂度会提高，但这是本次价值提升的关键。

## 本次设计结论

本次资产透视重做采用「首页建立洞察价值，详情页承接完整分析」的双层结构。首页以行业占比为主视觉，以集中度为风险补充；详情页以维度切换、金额 / 占比切换、分类列表和可下钻持仓为核心交互。实现时必须把数据归类链路一并补齐，否则统计能力无法在真实数据中成立。
